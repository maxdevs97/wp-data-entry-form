# Bug Fix: "Job not found" Error - Feb 20, 2026

## Problem Summary

Max submitted a migration and the progress screen showed contradictory information:
- Progress: 30%
- Stage: "extracting"
- Error: "Job not found. Please contact support."
- Items: 0 / 0

This was confusing because if the job wasn't found, how could there be progress?

## Root Cause Analysis

### Issue 1: Google Sheets API Rate Limiting
The application hit Google Sheets API rate limits (429 errors):
```
Error: Quota exceeded for quota metric 'Read requests' and limit 
'Read requests per minute per user'
```

**Why this happened:**
- Frontend polls job status every 3 seconds
- Job cache TTL was only 1 second
- Each poll hit the Sheets API (no effective caching)
- Multiple users/tabs polling simultaneously = quota exhaustion

### Issue 2: Silent Processor Crashes
When the backend processor tried to update job progress and hit rate limits:
- Sheets API returned 429 error
- `jobManager.updateProgress()` threw an exception
- No error handling = processor crashed silently
- Job stuck at last successful update (30% "extracting")

### Issue 3: Misleading Frontend Behavior
- Frontend successfully polled once (got 30% progress)
- Subsequent polls returned 404 or stale data
- Frontend kept displaying the last known state (30%)
- User saw progress bar + "Job not found" error simultaneously

## Fixes Implemented

### 1. Increased Cache TTL (`src/sheets.js`)
```javascript
// Before: 1 second for all jobs
const JOB_CACHE_TTL = 1000;

// After: Dynamic TTL based on job status
const JOB_CACHE_TTL_RUNNING = 10000;  // 10 seconds for active jobs
const JOB_CACHE_TTL_COMPLETE = 5000;  // 5 seconds for completed jobs
```

**Impact:** Reduces Sheets API calls by ~90% for running jobs

### 2. Added Exponential Backoff Retry (`src/sheets.js`)
```javascript
async function retryWithBackoff(fn, maxRetries = 3) {
  for (let attempt = 0; attempt < maxRetries; attempt++) {
    try {
      return await fn();
    } catch (error) {
      if (error.code === 429) {
        const backoffMs = Math.min(1000 * Math.pow(2, attempt), 10000);
        console.warn(`Rate limited. Retrying in ${backoffMs}ms...`);
        await new Promise(resolve => setTimeout(resolve, backoffMs));
        continue;
      }
      throw error;
    }
  }
}
```

**Impact:** Gracefully handles rate limits with 1s → 2s → 4s → 10s backoff

### 3. Wrapped All Sheets API Calls
All read/write operations now use `retryWithBackoff()`:
- `findJobRow()` - Job status queries
- `appendJob()` - New job creation
- `updateJobRow()` - Progress updates

**Impact:** No more crashes on transient rate limit errors

### 4. Safe Progress Updates (`src/processor.js`)
```javascript
async function safeUpdateProgress(jobId, updates, logger) {
  try {
    await jobManager.updateProgress(jobId, updates);
  } catch (error) {
    logger?.warn('Failed to update progress (continuing anyway)', { 
      error: error.message 
    });
  }
}
```

**Impact:** Processor continues even if Sheets updates fail

### 5. Reduced Frontend Polling Frequency (`public/status.js`)
```javascript
// Before: Poll every 3 seconds
setInterval(() => pollJobStatus(jobId), 3000);

// After: Poll every 5 seconds
setInterval(() => pollJobStatus(jobId), 5000);
```

**Impact:** 40% reduction in API calls from frontend
